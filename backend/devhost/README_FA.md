# میزبان توسعه ماژول مالی

این پوشه **فقط برای توسعه** است و هرگز نباید Deploy شود.

ماژول مالی عمداً Composition Root ندارد: طبق [INTEGRATION_GUIDE_FA.md](../INTEGRATION_GUIDE_FA.md)
میزبان BAMBO باید Connection دیتابیس، ۱۱ Service و ۶ Port را در `application.state` بگذارد.
تا وقتی آن میزبان در دسترس نباشد، هیچ راهی برای اجرای واقعی ماژول وجود ندارد و Frontend
ناچار روی Adapterهای Mock می‌ماند. این پوشه همان نقش را برای محیط محلی بازی می‌کند.

## اجرا

```bash
# ۱. وابستگی فقط-توسعه (سرور ASGI؛ عمداً در backend/requirements.txt نیست)
pip install -r devhost/requirements.txt

# ۲. میزبان (از پوشه backend)
python -m devhost
```

## اجرای تست‌ها

```bash
# از ریشه مخزن، داخل همان virtualenv
python -m pip install -r backend/requirements.txt -r backend/requirements-test.txt
python -m pytest backend/tests -q
```

اگر `No module named pytest` گرفتید یا خطای `no pq wrapper available` در مرحله Collection
دیدید، یعنی `requirements-test.txt` نصب نشده است. ابزار تست عمداً در
`backend/requirements.txt` نیست: ماژول مالی یک کتابخانه است و آن فایل همان چیزی است که
به میزبان تحویل می‌رود.

`psycopg[binary]` هم در همان فایل است، نه در فهرست Runtime — چون یک ماشین توسعه معمولاً
هیچ `libpq` سیستمی ندارد، ولی انتخاب اینکه یک میزبان Deploy شده `libpq` خودش را بیاورد یا
نه، تصمیم ما نیست.

اتصال از متغیر محیطی `FINANCE_DEV_DSN` خوانده می‌شود — پیش‌فرضی در کد وجود ندارد، چون
رشته اتصال رمز دارد و رمز نباید در مخزن باشد. `.env` را از `.env.example` بسازید.

PostgreSQL باید **Native** نصب و اجرا شده باشد. Docker در این پروژه استفاده نمی‌شود.

## ماندگاری داده

هرچه از رابط کاربری ثبت شود مستقیم در PostgreSQL می‌نشیند و با Restart میزبان توسعه
باقی می‌ماند. Seed **فقط وقتی اجرا می‌شود که پروژه نمونه اصلاً وجود نداشته باشد** — پس
داده‌ای که خودتان وارد کرده‌اید هرگز بازنویسی نمی‌شود.

تنها چیزی که داده را پاک می‌کند `--reseed` است. آن را روی دیتابیسی که کار واقعی
داخلش دارید اجرا نکنید.

سپس <http://127.0.0.1:8010> را باز کنید.

### بدون Docker

Docker فقط یک PostgreSQL محلی فراهم می‌کند و هیچ بخش دیگری از پروژه از آن خبر ندارد —
نه ماژول، نه Migrationها، نه تست‌ها، نه Frontend. هر PostgreSQL دیگری هم کار می‌کند:

```bash
python -m devhost --dsn "postgresql://user:pass@127.0.0.1:5432/bambo_finance"
# یا با متغیر محیطی
set FINANCE_DEV_DSN=postgresql://user:pass@127.0.0.1:5432/bambo_finance
```

برای نسخه قابل‌حمل (بدون Administrator، بدون Service، با حذف پوشه برگشت‌پذیر):
باینری‌های ویندوزی PostgreSQL را باز کنید، سپس

```bash
initdb -D <data> -U bambo --pwfile=<file> -E UTF8 --locale=C
# در postgresql.conf:  listen_addresses = 'localhost'   و   port = 55432
pg_ctl -D <data> -l server.log start
createdb -h 127.0.0.1 -p 55432 -U bambo bambo_finance
```

`listen_addresses = 'localhost'` را جدی بگیرید. پیش‌فرض روی همه رابط‌ها گوش می‌دهد،
و روی دستگاهی که VPN دارد یعنی دیتابیس روی آدرس تونل هم پاسخ می‌دهد.

گزینه‌ها:

| گزینه | کار |
|---|---|
| `--reseed` | پروژه نمونه را پاک و دوباره بارگذاری می‌کند |
| `--port` | پورت، پیش‌فرض `8010` (یا متغیر `FINANCE_DEMO_PORT`) |
| `--dsn` | رشته اتصال، یا متغیر محیطی `FINANCE_DEV_DSN` |

Migrationها در هر بار بالا آمدن اجرا می‌شوند و چون همگی `IF NOT EXISTS` هستند، تکرارشدنی‌اند.
Seed فقط وقتی اجرا می‌شود که پروژه نمونه وجود نداشته باشد، مگر با `--reseed`.

## چرا Frontend از حالت Mock خارج می‌شود

دو شرط باید هم‌زمان برقرار باشد:

1. **Context میزبان** — `bootstrap.js` با `getHostContext()` تصمیم می‌گیرد و آن هم
   `window.__BAMBO_FINANCE_CONTEXT__` را می‌خواند. این میزبان `index.html` را با آن شیء
   تزریق‌شده **پیش از** تگ `<script type="module">` سرو می‌کند.
2. **هم‌ریشه بودن** — `api-client.js` تابع `assertSameOrigin` دارد و درخواست به Origin دیگر
   را رد می‌کند. پس API و فایل‌های استاتیک باید از یک پروسه و یک پورت سرو شوند؛ همین کار
   اینجا انجام می‌شود.

## آنچه واقعی است و آنچه ساختگی

| بخش | وضعیت |
|---|---|
| Schema و داده | واقعی: PostgreSQL 16، همان Migrationهای تولید |
| محاسبات مالی | واقعی: همان Domain و Repositoryهای تولید |
| احراز هویت | **ساختگی**: یک کاربر ثابت با هر پنج مجوز مالی |
| عضویت سازمان و پروژه | **ساختگی**: فقط Tenant نمونه پذیرفته می‌شود |
| خوراک پیشرفت | **ساختگی**: Assignmentهای ثابت از `seed.py` |
| فهرست فعالیت‌ها | **ساختگی**: در حافظه |
| ذخیره فایل | محلی، زیر `devhost/.files` |
| استخراج AI | **غیرفعال**: عمداً خطا می‌دهد تا داده فاکتور جعل نشود |

## اگر دیتابیس Restart شود

میزبان توسعه خودش دوباره وصل می‌شود؛ لازم نیست Restartش کنید. اولین درخواست بعد از قطعی
با خطا برمی‌گردد و از دومی به بعد سالم است — عمدی است: دستوری که وسط کار قطع شده دوباره
اجرا نمی‌شود، چون تکرار خودکار یک نوشتن نیمه‌تمام بدتر از یک خطای قابل‌مشاهده است.

## دیدن داده

PostgreSQL هر جدول را در یک فایل باینری زیر `data/base/` نگه می‌دارد؛ آن فایل‌ها با هیچ
ویرایشگری قابل خواندن نیستند و نامشان هم ثابت نمی‌ماند. برای دیدن داده باید از خود سرور
پرسید:

```bash
cd backend

python -m devhost.inspect                 # همه جدول‌ها با تعداد ردیف
python -m devhost.inspect estimate_lines  # ردیف‌های یک جدول
python -m devhost.inspect --changes       # فقط آنچه از رابط کاربری آمده
python -m devhost.inspect --export        # یک CSV به‌ازای هر جدول
```

`--export` فایل‌ها را در `devhost/.export/` می‌نویسد و با UTF-8 BOM ذخیره می‌کند تا اکسل
متن فارسی را درست باز کند.

با `psql` هم می‌شود:

```bash
E:amboo\pgsql-dev\pgsqlin\psql.exe "postgresql://bambo@127.0.0.1:55432/bambo_finance_dev"
\dt                    فهرست جدول‌ها
\d estimate_lines      ساختار یک جدول
SELECT * FROM estimate_lines WHERE source = 'manual_entry';
```

## داده‌ها کجا ذخیره می‌شوند

| لایه | محل | محتوا |
|---|---|---|
> ### راه‌اندازی Host دیگر Migration اجرا نمی‌کند
>
> پیش‌تر اگر `FINANCE_MIGRATION_DSN` تنظیم بود، صرفِ بالا آوردن Host یک `alembic upgrade head`
> اجرا می‌کرد. این حذف شد: **اجرای یک برنامه، رضایت به تغییر Schema نیست**، و وجود DSN نقش
> Owner یک Credential است، نه یک دستور.
>
> Migration را صریح اجرا کنید:
>
> ```
> cd backend
> alembic upgrade head
> ```
>
> اگر Host را پیش از اعمال Migration بالا بیاورید، با پیام روشن متوقف می‌شود و همین دستور را
> به شما می‌گوید — به‌جای اینکه بی‌صدا Schema را بسازد.

> ### داده نمونه دیگر خودکار بارگذاری نمی‌شود
>
> Seed حالا **Fail-closed** است و دو شرط می‌خواهد:
>
> 1. `APP_ENV` **واقعاً تنظیم شده باشد** و یکی از `development` / `dev` / `test` باشد، و
> 2. `FINANCE_ALLOW_SEED=true` صریحاً تنظیم شده باشد.
>
> اگر `APP_ENV` تنظیم نشده باشد، حتی با `FINANCE_ALLOW_SEED=true` هم Seed مجاز نیست.
> دلیل: `APP_ENV` وقتی تنظیم نشده باشد مقدار `development` برمی‌گرداند — پیش‌فرضی مناسب برای
> *توصیف* محیط، ولی خطرناک برای *مجاز کردن* نوشتن. پس مسیر Seed مقدار خام را می‌خواند، نه
> مقدار پیش‌فرض‌دار را. **هیچ پیش‌فرضی نباید درج داده نمونه را مجاز کند.** `staging` هم از فهرست خارج شد: محیط Deploy شده است و فاکتور نمونه در آن دقیقاً شبیه
> فاکتور واقعی دیده می‌شود.
>
> اگر روی ماشین خودتان داده نمونه می‌خواهید، `FINANCE_ALLOW_SEED=true` را در `.env` بگذارید.
>
> **اولین Seed دیگر `reset` نمی‌کند.** رفتار حالا این است:
>
> | وضعیت | چه می‌شود |
> |---|---|
> | Seed مجاز نیست | هیچ کاری انجام نمی‌شود؛ حتی به دیتابیس وصل هم نمی‌شود |
> | `--reseed` صریح | `reset` و سپس `load` |
> | هنوز Seed نشده | فقط `load` |
> | قبلاً Seed شده | هیچ کاری |
>
> `reset()` برای دور ریختن داده کاری یک توسعه‌دهنده است، پس فقط وقتی اجرا می‌شود که کسی صریحاً
> بخواهد. `FINANCE_ALLOW_SEED=true` به‌تنهایی هرگز کافی نیست.

| **Schema** | Revisionهای Alembic در `backend/alembic/versions/` | فقط ساختار: جدول، Constraint، Trigger. هیچ داده‌ای ندارد و دست‌نخورده می‌ماند. Host توسعه در زمان راه‌اندازی `alembic upgrade head` را اجرا می‌کند. |
| **داده Seed** | `backend/devhost/seed.sql` | SQL خام و قابل ویرایش. با `python -m devhost.generate_seed_sql` از روی قواعد Mock بازتولید می‌شود. |
| **داده زنده** | PostgreSQL محلی (پیش‌فرض) یا Volume داکر `finance_finance-dev-data` | هرچه در UI ثبت کنید اینجا می‌نشیند و با Restart باقی می‌ماند. |
| **خوراک میزبان** | `backend/devhost/seed.py` | آنچه Port میزبان *سرو* می‌کند نه *ذخیره*: خوراک پیشرفت و فهرست فعالیت‌ها. |

پاک‌کردن کامل داده: روی سرور محلی با `--reseed`، و روی داکر با `docker compose ... down -v`.

## داده نمونه

یک پروژه ساختمانی با زیربنای ۱۴٬۲۵۰ مترمربع که هر مسیر محاسباتی را فعال می‌کند:

- **قیمت‌های تغییرکرده** پس از تصویب برآورد، در دو Scope سازمان و پروژه
- **جرثقیل بدون قیمت روز** تا مسیر «محاسبه ناقص» دیده شود، نه اینکه فرضی بماند
- **اضافه‌برداشت مقدار** در دیوارچینی → هشدار `QUANTITY_OVERRUN`
- **اضافه‌خرج هزینه عمومی** در عوارض شهرداری → هشدار `GENERAL_COST_OVERRUN`
- **خط بدون مقدار واقعی** تا Fallback درصد پیشرفت فعال شود
- فاکتورها در وضعیت‌های `confirmed`، `awaitingConfirmation` و `draft`

## هشدار

`ports.py` هویت را جعل می‌کند و همه مجوزها را می‌دهد. تنها اتصال بین این پوشه و
`backend/app` جهت وارد کردن است: `devhost` از `app` استفاده می‌کند، ولی `app` هرگز
از `devhost` چیزی وارد نمی‌کند. کد تولید از وجود این پوشه بی‌خبر است.
