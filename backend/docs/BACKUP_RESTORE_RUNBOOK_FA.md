# دستورالعمل پشتیبان‌گیری و بازیابی

هیچ رمز یا DSN واقعی در این سند نیست. `<...>` را از محیط انتشار بگیرید.

> **قاعده اول:** پشتیبانی که بازیابی‌اش آزموده نشده، پشتیبان نیست. بخش ۴ اختیاری نیست.

---

## ۰. دروازه هدف — قبل از هر دستور

```sql
SELECT current_database(), inet_server_addr(), inet_server_port(), version();
```

پیش از **پشتیبان‌گیری** تأیید کنید که به دیتابیس درست وصلید.
پیش از **بازیابی** تأیید کنید که به دیتابیسی وصلید که **قرار است بازنویسی شود**.

مرحله دوم مهم‌تر است: `pg_restore` روی دیتابیس اشتباه، همان چیزی است که این سند برای
جلوگیری از آن نوشته شده.

---

## ۱. پشتیبان‌گیری

```bash
pg_dump -Fc \
        -h <host> -p <port> -U <user> \
        -d <database> \
        -f <backup-dir>/<database>-$(date +%Y%m%d-%H%M%S).dump
```

**چرا `-Fc` (فرمت سفارشی):**

| | |
|---|---|
| فشرده است | حجم کمتر |
| **انتخابی بازیابی می‌شود** | می‌توانید فقط یک جدول را برگردانید |
| بدون بازیابی قابل بازرسی است | `pg_restore -l` |
| به ترتیب وابسته نیست | `pg_restore` خودش ترتیب را می‌چیند |

**نسخه Client مهم است:** `pg_dump` باید **هم‌نسخه یا جدیدتر** از سرور باشد. یک `pg_dump` قدیمی
روی سرور جدید یا کار نمی‌کند یا ساختارهایی را که نمی‌شناسد جا می‌اندازد.

```bash
pg_dump --version      # ثبتش کنید
```

**همیشه ثبت کنید:**

```
□ نسخه Client
□ نام فایل
□ حجم به بایت
□ زمان UTC
□ نام دیتابیس مبدأ و میزبانش
```

---

## ۲. بازرسی پشتیبان — بدون بازیابی

```bash
pg_restore -l <backup-file> | head -40           # فهرست محتویات
pg_restore -l <backup-file> | grep -c "TABLE DATA"   # چند جدول داده دارند
```

```
□ فایل خوانده می‌شود و خطا نمی‌دهد
□ تعداد جدول‌های داده‌دار منطقی است
□ حجم صفر یا نامتعارف کوچک نیست
```

> یک فایل صفر بایتی هم یک فایل است. تنها راه فهمیدن اینکه پشتیبان سالم است، خواندنش است.

---

## ۳. ساخت مقصد بازیابی

**هرگز روی دیتابیس زنده بازیابی نکنید.** همیشه یک دیتابیس تازه بسازید:

```sql
-- روی دیتابیس نگهداری (postgres)
CREATE DATABASE <restore_target>;
```

```
□ نام مقصد با نام مبدأ فرق دارد
□ مقصد تازه ساخته شده و خالی است
□ مقصد نام هیچ دیتابیس واقعی‌ای نیست
```

---

## ۴. بازیابی

```bash
pg_restore -h <host> -p <port> -U <user> \
           -d <restore_target> \
           --no-owner --no-privileges \
           <backup-file>
```

**چرا `--no-owner --no-privileges`:** مالکیت و مجوزها به نقش‌های سرور مبدأ اشاره می‌کنند که
ممکن است روی مقصد وجود نداشته باشند. برای یک بازیابی آزمایشی، داده اهمیت دارد نه ACL.

> برای بازیابی **واقعی** روی Production این دو را حذف کنید و مطمئن شوید نقش‌ها وجود دارند.

---

## ۵. اعتبارسنجی بازیابی

اعداد را دستی مقایسه نکنید. یک اثر انگشت قطعی بگیرید و دو طرف را برابر کنید:

```sql
-- ۱. نسخه Schema
SELECT version_num FROM finance_alembic_version;          -- باید 0006 باشد

-- ۲. تعداد جدول‌ها
SELECT count(*) FROM information_schema.tables
 WHERE table_schema = 'public' AND table_type = 'BASE TABLE';

-- ۳. شمارش هر جدول
SELECT relname, n_live_tup FROM pg_stat_user_tables ORDER BY relname;

-- ۴. مجموع مالی که باید دقیقاً بخواند
SELECT sum(il.final_line_amount_irr * i.financial_effect_sign) AS confirmed_actual
  FROM invoice_lines il JOIN invoices i ON i.id = il.invoice_id
 WHERE i.status IN ('confirmed','voided','corrected');

-- ۵. اثر انگشت محتوا
SELECT md5(string_agg(k || '~' || a || '~' || b, '|' ORDER BY k, a, b)) AS digest
FROM (
  SELECT 'settings' k, revision::text a, gross_built_area::text b
    FROM finance_project_settings
  UNION ALL SELECT 'estimate', id::text, coalesce(original_quantity::text,'-')
    FROM estimate_lines
  UNION ALL SELECT 'price', id::text, unit_price_irr::text FROM price_versions
  UNION ALL SELECT 'invoice', id::text, final_amount_irr::text FROM invoices
) s;
```

```
□ finance_alembic_version یکسان
□ تعداد جدول‌ها یکسان
□ شمارش هر جدول یکسان
□ جمع هزینه واقعی تأییدشده یکسان
□ اثر انگشت یکسان
```

**اثر انگشت مهم‌ترین است:** شمارش می‌گوید چند ردیف هست؛ اثر انگشت می‌گوید همان ردیف‌ها هستند.

---

## ۶. اگر بازیابی شکست خورد

**دیتابیس زنده را دست نزنید.** بازیابی روی یک مقصد جدا انجام شده، پس هیچ‌چیز از دست نرفته.

| نشانه | معنی | اقدام |
|---|---|---|
| `pg_restore` خطای نسخه داد | Client قدیمی‌تر از سرور مبدأ | Client هم‌نسخه بگیرید |
| خطای «relation already exists» | مقصد خالی نبوده | مقصد را حذف و دوباره بسازید |
| خطای نقش/مالکیت | نقش‌های مبدأ روی مقصد نیستند | `--no-owner --no-privileges` |
| فایل خوانده نمی‌شود | پشتیبان خراب است | **پشتیبان قبلی را امتحان کنید و این را غیرقابل‌اعتماد علامت بزنید** |
| اثر انگشت نمی‌خواند | داده کامل نیامده | بازیابی را قبول نکنید؛ علت را پیدا کنید |

> ردیف ماقبل آخر بدترین است: یعنی از لحظه‌ای که آن پشتیبان گرفته شده تا حالا، شبکه ایمنی
> نداشته‌اید و نمی‌دانستید. **به همین دلیل بازرسی بخش ۲ اختیاری نیست.**

## ۸. نگهداری فایل پشتیبان

```
□ بیرون از مخزن Git
□ در .gitignore اگر مسیرش داخل درخت پروژه است
□ دسترسی محدود — یک پشتیبان، کل داده مالی است
□ در خروجی لاگ و Terminal چاپ نمی‌شود
```

**فایل‌های این فاز** در `backend/.release-validation/` هستند و Git نادیده‌شان می‌گیرد.
