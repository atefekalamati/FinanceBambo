## ۱. پاسخ به پرسش کسب‌وکار

> وقتی Sheet قیمت روزانه به‌روز می‌شود، آیا BAMBO پایگاه داده را به‌روز می‌کند؟

**تا پیش از این تغییر: نه.**

`price_observations` دقیقاً **یک** نویسندهٔ تولیدی دارد
(`repositories/material_prices.py:260`) که فقط از طریق `MaterialPriceImportService`
در دسترس است، و آن سرویس تا امروز فقط از دو اسکریپت CLI صدا زده می‌شد:

* `scripts/import_material_prices.py`
* `scripts/ops/import_into_terrace.py`

**هیچ Scheduler، Worker، Cron یا Webhookی وجود ندارد.** ستون
`price_providers.default_interval_minutes` روی هر ۸ ردیف مقدار `1440` دارد و **هیچ کدی
آن را نمی‌خواند** — تنها مصرف‌کننده‌هایش دستورهای INSERT هستند. یعنی «روزانه» یک نیت
ذخیره‌شده بود، نه یک رفتار.

پس الگوی واقعی **D** بود: *اسکریپت دستی، Sheet را وارد پایگاه داده می‌کند.*

`POST /imports/prices/commit` این کار را **نمی‌کند** — آن Importer دیگری است که از فایل
Excel آپلودی به `price_versions` و `estimate_lines` می‌نویسد (قیمت رسمی Finance)، نه
مشاهدات بازار.

آخرین Import موفق: **۲۰۲۶-۰۹-۱۴** — دو روز پیش از این ممیزی.

### جریان داده، حالا

```
Google Sheet (یک سند، ۷ برگه)
   │  FINANCE_MATERIAL_PRICE_SHEET_URL  ← پیکربندی، نه پارامتر درخواست
   ▼
زمان‌بند Backend (روزانه، فقط در صورت رسیدن موعد)
   │   یا  POST /material-prices/import-runs   ← n8n / اپراتور
   │   یا  CLI، مثل قبل
   ▼
MaterialPriceImportService.run(scope)
   ├─ کل Workbook خوانده می‌شود؛ اگر برگه‌ای غایب/خالی باشد هیچ‌چیز نوشته نمی‌شود
   ├─ price_collection_runs  ← یک Run؛ Index یکتای جزئی مانع دو Import هم‌زمان است
   ├─ اعتبارسنجی سطر به سطر
   ├─ provider_items          ← ساخت یا تطبیق
   └─ price_observations      ← فقط افزودنی (Trigger)، Fingerprint مانع تکرار
   ▼
GET /material-prices/current   ← تازه‌ترین مشاهدهٔ **معتبر**
   ▼
اقلام و برآورد / گزارش‌های مالی
```

## ۴. نقصی که پیدا شد — و مهم بود

**یک سطر ردشده با تاریخ جدیدتر، قیمت معتبر را پنهان می‌کرد.**

`latest_observations` فقط بر اساس تاریخ مرتب می‌کرد. پس روزی که تأمین‌کننده در Sheet
«تماس بگیرید» می‌نوشت:

1. آن سطر با تاریخ کسب‌وکارِ **جدیدتر** وارد می‌شد،
2. `DISTINCT ON` را می‌برد،
3. و قیمت جاری محصول `null` می‌شد — `invalid_source`، بدون عدد، در هر برآوردی.

در همان جدول، قیمت کاملاً معتبرِ سه روز پیش نشسته بود و هیچ API آن را برنمی‌گرداند.

**اثبات شد** (پروژهٔ `selection_probe_204205`): قیمت معتبر ۹۵۵٬۰۰۰ در ۲۰۲۶-۰۹-۱۳ وجود
داشت و API `None` می‌داد.

### اصلاح

کلید مرتب‌سازی اول اضافه شد:

```sql
ORDER BY o.provider_item_id,
         (o.validation_status = 'valid'
          AND o.workflow_date_gregorian IS NOT NULL) DESC,   ← اصلاح
         o.workflow_date_gregorian DESC NULLS LAST,
         o.fetched_at DESC, o.id
```

سطری که باورپذیر نبوده نباید به همین دلیل چیزی شود که همه باور می‌کنند.

**فیلتر نیست، مرتب‌سازی است** — پس فهرستی که همهٔ مشاهداتش نامعتبرند همچنان دیده می‌شود
با قیمت null و دلایلش. «این محصول را داریم و نمی‌توانیم قیمتش بزنیم» پاسخی است که
خواننده لازم دارد؛ سکوت نیست.

و کنارگذاشتن **ساکت نیست**: سه فیلد تازه می‌گویند سطر جدیدتری رد شده:

```json
"rejectedAfterDate": "2026-09-16",
"rejectedAfterRawPrice": "تماس بگیرید",
"rejectedAfterReasons": ["price is not a number: 'تماس بگیرید'"]
```

## ۶. آنچه بررسی شد و سالم بود

* **افزودنی بودن** — Trigger `price_observations_immutable` هر UPDATE/DELETE را رد می‌کند (عملاً اثبات شد).
* **Fingerprint** — `(productId، تاریخ ورک‌فلو، قیمت)` هش‌شده، با Index یکتای جزئی در دامنهٔ `(org, project, provider_item)` — تکرارِ مشروعِ چندپروژه‌ای نمی‌شکند.
* **حفاظت از Sheet نیمه‌کاره** — اگر برگه‌ای غایب یا خالی باشد، **هیچ‌چیز** نوشته نمی‌شود و قیمت‌های قبلی دست‌نخورده می‌مانند.
* **تاریخ** — نه `fetched_at` و نه امروز جایگزین تاریخ کسب‌وکار نمی‌شوند (دو تست اختصاصی).
* **Snapshotها** — روی هر مشاهدهٔ تازه نوشته می‌شوند.
* **هیچ دادهٔ Mock در Runtime نیست** — تمام برخوردهای `mock/fake/sample` در `app/` و `coreint/` توضیح‌اند نه کد؛ Seed فقط در `devhost/` و پشت `seeding_allowed()` + `FINANCE_MIGRATION_DSN`.

## ۷. زمان‌بند Backend (افزوده‌شده)

دو متغیر محیطی، هر دو در حالت **خاموش** مگر صریحاً روشن شوند:

```
FINANCE_MATERIAL_PRICE_IMPORT_ENABLED=yes
FINANCE_MATERIAL_PRICE_IMPORT_INTERVAL_MINUTES=1440
```

Hostی که هرگز به آن گفته نشده روزانه Import کند، با Restart شدن شروع نمی‌کند.

### رفتار

| موضوع | قاعده |
|---|---|
| **کدام پروژه‌ها** | آن‌هایی که Provider فعال از نوع `google_sheet` دارند — از `price_providers` خوانده می‌شود، نه فهرست دومی که کسی باید هماهنگش نگه دارد |
| **چه زمانی** | وقتی تازه‌ترین Run **موفق** بیش از بازه پیش شروع شده باشد |
| **چرا «موفق»** | Runی که شکست خورده قیمت‌ها را دست‌نخورده گذاشته؛ شمردنش به‌عنوان «امروز Import کردیم» یعنی یک Sheet خراب، Importer را یک روز ساکت می‌کند به‌جای اینکه دوباره تلاش شود |
| **پروژهٔ تازه** | `minutes_since_last_success = NULL` ⇒ در همان Tick بعدی Import می‌شود، نه یک روز بعد |
| **force** | فقط بررسی موعد را رد می‌کند و نه چیز دیگر — کسی که همین حالا Import می‌خواهد، نمی‌پرسد وقتش رسیده یا نه |
| **هم‌پوشانی** | Index یکتای جزئی روی Runهای در حال اجرا؛ Tick دوم به‌عنوان `failed` گزارش می‌شود نه استثنا |
| **شکست** | **خروجی است، نه Exception.** حلقه‌ای که با یک Sheet خراب می‌میرد، Import همهٔ پروژه‌های دیگر را هم متوقف می‌کند و علامتش سکوت است |
| **بازهٔ نامعتبر** | `0`، منفی، یا غیرعددی ⇒ بازگشت به ۱۴۴۰. صفر یعنی «همیشه موعد»، که حلقهٔ تنگ روی سرور دیگران است |

Tick اول بلافاصله پس از بالا آمدن اجرا می‌شود (Hostی که یک روز خاموش بوده نباید یک روز
دیگر صبر کند) و بررسی موعد **پیش از** Fetch انجام می‌شود، پس Restart پیاپی به Google
فشار نمی‌آورد.

### خروجی هر Tick

```
material price import [terrace] imported {'runStatus': 'succeeded', 'inserted': 1, 'alreadyPresent': 6, 'rejected': 0}
material price import [sample_site_01] skipped {'minutesSinceLastSuccess': 12.4}
```

«هیچ‌کاری نکرد» و «اصلاً اجرا نشد» در Log یکسان به نظر می‌رسند مگر اینکه پرش گزارش شود.

### اثبات زنده (پروژهٔ `sched_probe_20260916_212029`) — ۱۱ قبول، ۰ رد

| بررسی | نتیجه |
|---|---|
| پروژهٔ بدون Provider در فهرست Tick نیست | ✓ |
| Tick با `dueOnly` بلافاصله بعد از موفقیت | **skipped**، صفر نوشتن |
| `force` با وجود نبودن موعد | **imported**، `inserted=1` |
| `force` دوبارهٔ همان Sheet | صفر نوشتن، `inserted=0` |
| API قیمت جاری | ۹۹۰٬۰۰۰ در ۲۰۲۶-۰۹-۱۶ (تازه‌ترین معتبر) |
| **روز قبلی هنوز در تاریخچه** | ۹۵۵٬۰۰۰ در ۲۰۲۶-۰۹-۱۳ — **دست‌نخورده** |
| بازهٔ صفر | به ۱۴۴۰ برگشت |

## ۸. کلید سرویس برای n8n

n8n آدم نیست: نشستی ندارد، در هیچ دایرکتوری نیست، و دادن حساب کاربری به آن یعنی گذاشتن
یک لاگین در یک Password Manager و اسمش را «هویت» گذاشتن. پس یک **کلید مشترک** می‌فرستد،
و آن کلید روی **یک مسیر** پذیرفته می‌شود.

```
FINANCE_MATERIAL_PRICE_IMPORT_SERVICE_KEY=<حداقل ۳۲ کاراکتر تصادفی>
```

```http
POST /api/projects/{projectId}/finance/material-prices/import-runs?force=true
X-FINANCE-SERVICE-KEY: <کلید>
```

بدون Body.

### حصار دور کلید

| کلید چه می‌تواند | کلید چه نمی‌تواند |
|---|---|
| یک Import را شروع کند | Sheet را انتخاب کند (پیکربندی سرور است) |
| — | سازمان را انتخاب کند (از پیکربندی Provider همان پروژه خوانده می‌شود) |
| — | به هیچ مسیر دیگری برسد (تستی این را pin می‌کند) |
| — | مجوزی بگیرد؛ چیزی برای ارتقا وجود ندارد |
| — | کاربری را جعل کند؛ هیچ شناسهٔ کاربری در Header نیست |

پروژه‌ای که Provider فعال ندارد **اصلاً با این کلید در دسترس نیست** — چیزی برای Import
نیست، پس سازمانی هم برای استنتاج نیست و جواب رد است نه حدس.

### رفتار

| درخواست | نتیجه |
|---|---|
| بدون Header | مسیر انسانی، `finance.edit` — **بدون تغییر** |
| Header با کلید درست | اجرا، بدون بررسی مجوز · `initiatedBy: system` |
| Header با کلید غلط | **۴۰۱** `FINANCE_SERVICE_KEY_REJECTED` |
| Header روی Hostی که کلید ندارد | **۴۰۱** |
| کلید کوتاه‌تر از ۳۲ کاراکتر در محیط | Host هیچ کلیدی نمی‌پذیرد |

مقایسه با `hmac.compare_digest` انجام می‌شود — `==` به‌محض اختلاف اولین بایت برمی‌گردد و
آن زمان، اندازه‌گیریِ این است که مهاجم چقدر از کلید را حدس زده. کلید هرگز Log نمی‌شود،
هرگز در پاسخ نمی‌آید، و در پیام خطا هم تکرار نمی‌شود.

### ردیابی

پاسخ می‌گوید چه کسی خواسته:

```json
{"status":"succeeded","inserted":880,"alreadyPresent":1221,"rejected":109,
 "triggerSource":"n8n_daily_material_price_update","initiatedBy":"system"}
```

`initiatedBy` برای اجرای خودکار `system` است، نه یک کاربر ساختگی — گذاشتن نامی در
Audit Trail که به هیچ‌کس تعلق ندارد، بدتر از نگذاشتن آن است.

## ۹. آنچه هنوز باقی است
* Endpoint فقط وقتی سیم‌کشی می‌شود که `FINANCE_MATERIAL_PRICE_SHEET_URL` تنظیم باشد؛
  در غیر این صورت ۴۰۹ با کد `MATERIAL_PRICE_SHEET_NOT_CONFIGURED` می‌دهد و Host هنگام
  بالا آمدن این را چاپ می‌کند.
* پروژه‌های Probe (`ingestion_probe_*`، `selection_probe_*`) در پایگاه دادهٔ آزمون
  می‌مانند، چون جدول افزودنی است.
