# راهنمای عملیاتی قیمت مصالح

این سند برای کسی است که باید درون‌ریزی قیمت مصالح را اجرا، بررسی یا خاموش کند.

---

## ۱. متغیرهای محیطی

| متغیر | لازم؟ | پیش‌فرض | معنی |
|---|---|---|---|
| `FINANCE_MATERIAL_PRICE_SHEET_URL` | برای درون‌ریزی، بله | **تنظیم‌نشده** | نشانی برگهٔ گوگل |
| `FINANCE_MIGRATION_DSN` | برای اجرای مهاجرت | — | نقشی که DDL می‌زند |
| `FINANCE_DEV_DSN` | برای اجرای میزبان | — | نقش زمان اجرا |

**پیش‌فرضِ نبودن یعنی خاموش.** اگر `FINANCE_MATERIAL_PRICE_SHEET_URL` تنظیم نشده باشد، هیچ
درون‌ریزی‌ای اجرا نمی‌شود و هیچ چیزی نوشته نمی‌شود. این عمدی است: خواندن صفحه‌گسترده ی کسی
نباید چیزی باشد که یک فرایند به‌خاطر فراموش‌شدن یک متغیر شروع کند.

نشانی برگه **پیکربندی** است، نه پارامتر درخواست. هیچ endpointای آن را نمی‌پذیرد — کسی که
بتواند برگه را نام ببرد، می‌تواند این میزبان را به هر برگه‌ای وصل کند.

هیچ اعتبارنامه‌ای لازم نیست و هیچ‌کدام در کد نیست: برگه باید روی «هرکس با لینک، مشاهده»
باشد. اگر نباشد، گوگل صفحهٔ ورود برمی‌گرداند و سرویس با پیام روشن رد می‌کند — چون بایت اول
را نگاه می‌کند، نه کد وضعیت را.

---

## ۲. اجرای دستی درون‌ریزی

**اول همیشه dry-run** — چیزی نمی‌نویسد و به دیتابیس هم وصل نمی‌شود:

```
cd backend
set FINANCE_MATERIAL_PRICE_SHEET_URL=<sheet url>
python -m scripts.import_material_prices --dry-run
```

خروجی می‌گوید هر worksheet خوانده شد یا نه، چند ردیف پذیرفته و چند ردیف رد شد، و آیا
workbook به‌عنوان یک کل قابل انتشار است.

اجرای واقعی روی یک دیتابیس **دورریختنی**:

```
python -m scripts.import_material_prices ^
  --dsn postgresql://postgres@127.0.0.1:5432/bambo_material_price_test ^
  --organization <uuid> --project <project id>
```

اسکریپت این دیتابیس‌ها را **رد می‌کند**، دو بار (یک‌بار از روی DSN و یک‌بار از روی پاسخ خود
سرور): `bambo`، `bambo_canonical_local`، `bambo_canonical_test`.

---

## ۳. دیدن وضعیت آخرین درون‌ریزی

از API:

```
GET /api/projects/{projectId}/finance/material-prices/runs
```

هر run می‌گوید چه زمانی شروع و تمام شد، چند ردیف موفق و چند ردیف رد شد، و اگر شکست خورده
چرا. `worksheetReport` جزئیات هر worksheet را دارد.

ردیف‌هایی که ذخیره شدند ولی قابل باور نبودند:

```
GET /api/projects/{projectId}/finance/material-prices/invalid-rows
```

این‌ها پنهان نیستند و پاک هم نشده‌اند — پیدا کردنی‌اند.

از دیتابیس:

```sql
SELECT status, started_at, finished_at, total_items, successful_items,
       rejected_items, error_message
  FROM price_collection_runs
 WHERE organization_id = %s AND project_id = %s
 ORDER BY started_at DESC LIMIT 5;
```

## ۴. خاموش کردن درون‌ریزی

`FINANCE_MATERIAL_PRICE_SHEET_URL` را بردارید. همین. هیچ زمان‌بندی‌ای هم وجود ندارد که
لازم باشد جدا خاموش شود: در این نسخه درون‌ریزی فقط دستی است.

---

## ۵. وقتی قالب برگه خراب می‌شود

اگر ستون `قیمت` نامش عوض شود، یا worksheetای خالی یا حذف شود:

- درون‌ریزی **رد می‌شود** و **هیچ چیزی نمی‌نویسد**.
- قیمت‌های فعلی **دست‌نخورده** می‌مانند.
- پیام خطا نام ستون یا worksheet گم‌شده را می‌گوید.

کاری که باید کرد: برگه را به قالب قبلی برگردانید و دوباره اجرا کنید. اگر تغییر قالب عمدی
است، `REQUIRED_HEADERS` یا `WORKSHEET_ALLOWLIST` در
`app/finance/services/material_price_sheet.py` باید آگاهانه به‌روز شود — نه به‌صورت خودکار.

**یک ستون تازه هیچ چیزی را خراب نمی‌کند** و نادیده گرفته می‌شود. فقط نبودِ یک ستون اجباری
جلوی کار را می‌گیرد.

---

## ۶. بررسی قیمت‌ها بعد از درون‌ریزی

```
GET /api/projects/{projectId}/finance/material-prices/current?asOf=2026-09-14
```

هر قلم یک `resolutionStatus` دارد:

| وضعیت | یعنی |
|---|---|
| `resolved` | قیمت هست و قابل استفاده است |
| `stale` | قیمت هست ولی قدیمی است — **نمایش داده می‌شود** و برچسب می‌خورد |
| `unresolved_price` | آخرین مشاهده قیمت خوانا نداشت |
| `unresolved_unit` | قیمت هست ولی ضریب تبدیل به واحد نمایش وجود ندارد |
| `unmapped` | قیمت هست ولی به قلم هزینهٔ مالی وصل نشده |

**هیچ‌کدام از این‌ها صفر برنمی‌گرداند.** `currentPriceIrr` در حالت‌های حل‌نشده `null` است.

در UI: صفحهٔ «قیمت روز» → بخش «قیمت روز بازار (برگه مصالح)» → دکمهٔ «نمایش قیمت روز بازار».

## ۷. برگرداندن کد

```
git revert <commit>        # یا
git checkout <previous commit> -- backend/app/finance/services/material_price_*.py
```

مهاجرت `0021` جدا برگردانده می‌شود:

```
cd backend
set FINANCE_MIGRATION_DSN=<dsn>
python -m alembic downgrade 0020
```

این دو جدول تازه و ده ستون تازه را حذف می‌کند. **توجه:** اگر ردیفی با
`provider_type='spreadsheet'` وجود داشته باشد، downgrade **رد می‌شود** — و باید بشود. حذف
یک تأمین‌کننده برای اینکه downgrade موفق شود یعنی نابود کردن همان چیزی که downgrade برای
محافظت از آن هست.

---

## ۸. آنچه این درون‌ریزی هرگز نمی‌کند

- `price_versions` نمی‌نویسد. قیمت رسمی مالی تصمیم یک انسان است.
- `estimate_lines`، `invoices`، `report_snapshots` را لمس نمی‌کند.
- ردیفی را حذف نمی‌کند. محصولی که از برگه رفت، رکوردش می‌ماند و فقط مشاهدهٔ تازه نمی‌گیرد.
- قیمت خالی را صفر نمی‌کند.
- تاریخ ناخوانا را «امروز» نمی‌کند.
- فرمول‌های برگه را اجرا نمی‌کند (`data_only=True`).
- هیچ آدرسی از داخل سلول‌ها را دنبال نمی‌کند.

---

## ۹. استقرار روی Production

**این بخش هنوز تأیید جداگانه می‌خواهد و در این مأموریت انجام نشده است.**

ترتیب پیشنهادی، برای بازبینی:

1. پشتیبان کامل از `bambo_canonical_local`.
2. `alembic upgrade head` روی یک کپی بازیابی‌شده، و مقایسهٔ ساختار.
3. اجرای `0021` روی Production در یک پنجرهٔ اعلام‌شده (فقط افزایشی است و هیچ داده‌ای
   نمی‌نویسد).
4. تنظیم `FINANCE_MATERIAL_PRICE_SHEET_URL` روی میزبان.
5. یک dry-run.
6. اولین درون‌ریزی واقعی، و بررسی `runs` و `invalid-rows`.
7. تصمیم‌گیری دربارهٔ واحد نمایش هر دسته، از طریق UI و توسط کاربر مجاز.

هیچ‌کدام از این مراحل در این مأموریت روی Production اجرا نشده است.
