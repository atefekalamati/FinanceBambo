# استخراج تصویر و صوت — قرارداد Provider

## وضعیت امروز

هیچ Provider واقعی پیکربندی نشده. میزبان توسعه `UnavailableExtractor` را سیم‌کشی می‌کند که
یک کار می‌کند: **صریح شکست می‌خورد**.

```
503  FINANCE_EXTRACTION_UNAVAILABLE
```

> **هیچ خروجی AI ساختگی تولید نمی‌شود.** یک Stub که فاکتور محتمل‌به‌نظر برمی‌گرداند، بدتر
> از این خطاست: اعداد وارد یک گزارش مالی می‌شوند و هیچ‌چیزِ پایین‌دست نمی‌تواند تشخیص دهد
> ساختگی بوده‌اند.

**۵۵ از ۵۷ مسیر بدون این دو Provider کار می‌کنند.** این یک بازدارنده Production است، ولی
اگر MVP استخراج خودکار نخواهد، **الزامی نیست**.

---

## قرارداد

```python
class InvoiceImageExtractor(Protocol):
    adapter_name: str
    async def extract(self, file, hints: Mapping[str, object]) -> object: ...

class InvoiceVoiceExtractor(Protocol):
    adapter_name: str
    async def extract(self, file, hints: Mapping[str, object]) -> object: ...
```

`adapter_name` اختیاری نیست: در پیش‌نویس استخراج ثبت می‌شود، تا بعداً معلوم باشد کدام
Provider و کدام نسخه، این اعداد را پیشنهاد داده است.

### ورودی

| | |
|---|---|
| `file` | فراداده پیوست: نوع منطقی، MIME، حجم، SHA-256، کلید ذخیره |
| `hints` | زمینه‌ای که مالی می‌داند: منابع پروژه، واحدها، تاریخ گزارش |

`hints` پیشنهاد است، نه دستور. Provider مجاز است نادیده بگیرد.

### خروجی

فهرستی از فیلدهای استخراج‌شده، هرکدام با:

```
key               نام فیلد (شماره فاکتور، تاریخ، فروشنده، مبلغ، ردیف‌ها)
extractedValue    آنچه Provider خواند — یا null اگر نخواند
confidence        عدد بین ۰ و ۱
```

**هر فیلد باید `confidence` داشته باشد.** رابط کاربری بر اساسش تصمیم می‌گیرد چه چیزی را به
کاربر برای تأیید نشان دهد. Providerی که همه‌چیز را ۱٫۰ اعلام کند، بازبینی انسانی را بی‌معنا
می‌کند.

> **هیچ خروجی استخراج مستقیم به فاکتور تبدیل نمی‌شود.** همیشه یک `extraction_draft` می‌شود
> که انسان تأیید یا رد می‌کند، و تأییدش رویدادی ممیزی‌شده است.

## پیکربندی لازم

این‌ها را **میزبان** فراهم می‌کند، نه ماژول مالی. مالی هیچ متغیر محیطی نمی‌خواند.

| مورد | چرا |
|---|---|
| اعتبار Provider | کلید API یا حساب سرویس |
| Endpoint | ناحیه/میزبان سرویس |
| **Timeout** | بدون آن، یک درخواست کند، کل Worker را نگه می‌دارد |
| سقف تلاش مجدد | استخراج، هزینه‌دار است؛ تلاش بی‌حد، صورت‌حساب می‌سازد |
| زبان | فارسی برای هر دو |

**پیشنهاد Timeout:** تصویر ۳۰ ثانیه، صوت ۱۲۰ ثانیه. صوت بلندتر است و باید Transcribe شود.

## رفتار در خطا

| وضعیت | پاسخ | چرا |
|---|---|---|
| Provider پیکربندی نشده | `503` | امروز همین است و درست است |
| Provider Timeout کرد | `503` | کاربر دوباره تلاش کند |
| Provider خطا داد | `503` + `adapter_name` در لاگ | تشخیص اینکه کدام Provider |
| فایل ناخوانا بود | `422` | مشکل ورودی است، نه سرویس |
| اطمینان پایین | **۲۰۰ با پیش‌نویس** | خطا نیست؛ کاربر باید ببیند و تصمیم بگیرد |

> ردیف آخر مهم است: اطمینان پایین یک **نتیجه** است، نه یک شکست. پنهان‌کردنش پشت خطا، کاربر
> را از داده‌ای محروم می‌کند که شاید بتواند تصحیحش کند.

## چک‌لیست

```
□ adapter_name نسخه Provider را هم می‌گوید
□ هر فیلد confidence دارد
□ Timeout تنظیم شده
□ اعتبارها از میزبان می‌آیند، نه از این مخزن
□ شکست، 503 می‌دهد — نه پیش‌نویس خالی
□ هیچ مسیری خروجی استخراج را مستقیم به فاکتور تبدیل نمی‌کند
```
