# بستهٔ دیپلوی ماژول مالی

**چه چیزی روی سرور می‌رود، و چه چیزی نه.**

---

## ساختن بسته

```bash
cd frontend
node scripts/build-package.mjs               # ../finance-package
node scripts/build-package.mjs /path/to/out  # یا هر جای دیگر
```

**فهرست دستی ننویسید.** اسکریپت همان گرافی را می‌پیماید که مرورگر می‌پیماید — هر
`import` از `src/app/bootstrap.js`، هر `@import` از `src/shared/styles/index.css`، و هر
فایلی که این دو نام می‌برند. اگر فایلی از گراف پیدا نشود، **چیزی نمی‌نویسد و با خطا
متوقف می‌شود** — چون بسته‌ای که بی‌صدا یک ماژول کم دارد، بدتر از نبودن بسته است.

هر بار که ماژول جدیدی اضافه شود، اسکریپت خودش پیدایش می‌کند.

## کدام HTML

| فایل | نقش |
|---|---|
| **`host.html`** | **نسخهٔ مرجع mount.** الگویی که تیم میزبان از آن کپی می‌کند |
| `index.html` | پیش‌نمایش مستقل با دادهٔ نمایشی. **میزبان از این کپی نکند** |

> ⚠️ **مهم‌ترین نکتهٔ این سند.** `index.html` روی `<body>` نشانگر
> `data-finance-runtime="standalone"` دارد. اگر صفحهٔ میزبان از آن کپی شود،
> **ماژول روی سایت اصلی دادهٔ ساختگی نشان می‌دهد.**
>
> `host.html` این نشانگر را ندارد و تنها چیزی که لازم دارد این است:
>
> ```html
> <main id="finance-module-root" tabindex="-1"></main>
> ```

## چه چیزی عمداً می‌رود، گرچه لازم به نظر نمی‌رسد

### `src/adapters/mock/` — ۱۱۷ کیلوبایت

**دادهٔ نمایشی روی سرور تولید می‌رود و هرگز اجرا نمی‌شود.**

قاعده در `runtime-context.js` صریح است:

```js
// A supplied but invalid context must never fall back to demo data.
if (hostContext) return { runtime: "host", ... };
if (mode === "standalone") return { runtime: "standalone", ... };
throw new Error("اطلاعات پروژه از سایت اصلی دریافت نشده است…");
```

| حالت | نتیجه |
|---|---|
| Context پیدا شود | دادهٔ واقعی |
| Context نباشد و نشانگر `standalone` باشد | دادهٔ ساختگی |
| Context نباشد و نشانگر نباشد | **خطای صریح** |

**دادهٔ ساختگی هرگز fallback نیست.**

**چرا پس حذف نمی‌شود؟** `bootstrap.js` نُه `import` **ایستا** از آن دارد. کیت bundler را
ممنوع کرده، پس tree-shaking وجود ندارد. حذف پوشه یعنی:

```
GET /src/adapters/mock/settings-adapter.js  →  404
        ↓
ماژول ES بارگذاری نمی‌شود  →  bootstrap.js اجرا نمی‌شود  →  صفحهٔ سفید
```

و **تست‌ها نمی‌گیرندش** — در توسعه فایل‌ها هستند. خرابی فقط روی سرور میزبان، روز اول،
بدون هیچ پیامی در کنسول ظاهر می‌شود.

۱۱۷ کیلوبایت (~۳۰ با gzip) در ازای صفر ریسک. برای حذف امن، آن نُه import باید پویا شوند —
تغییری با ریسک خودش، برای بعد از دیپلوی.

## آنچه از سرور خواسته می‌شود

```nginx
gzip on;
gzip_types application/javascript text/css image/svg+xml;
```

**اندازه‌گیری شده: ۸۶۴ KB جاوااسکریپت با gzip به ۲۲۴ KB می‌رسد.** بزرگ‌ترین برد به ازای
کمترین کار در کل این پروژه، و یک خط تنظیم است.

HTTP/2 هم ارزش دارد: ۱۲۹ درخواست روی HTTP/1.1 در صف می‌ایستند.

ماژول باید **هم‌مبدأ** با API سرو شود. `api-utils.js` مسیر ثابت
`/api/projects/{projectId}/finance` می‌سازد و `api-client.js` هر درخواست غیرهم‌مبدأ را
پیش از ارسال رد می‌کند.

## ⚠️ آنچه بعد از دیپلوی کار نمی‌کند

ماژول بالا می‌آید و همهٔ صفحات باز می‌شوند، ولی تا وقتی تیم بامبو دو مجوز را در جدول
`permissions` ثبت نکرده:

| قابلیت | روز اول |
|---|---|
| داشبورد · گزارش‌ها · نمودارها · اقلام · قیمت · پیشرفت | ✅ |
| ثبت فاکتور · تأیید · ابطال · اصلاحیه | ❌ ۴۰۳ |
| آپلود عکس/ویس · استخراج AI | ❌ ۴۰۳ |
| دیدن فایل اصلی فاکتور | ❌ ۴۰۴ |
| ثبت گزارش رسمی | ❌ ۴۰۳ |

```
finance.manage_invoice   |  مدیریت فاکتورها
finance_report.issue     |  صدور گزارش رسمی مالی
```

**این خرابی نیست، پیکربندی است** — ولی اگر در تحویل ننویسید، روز اول به‌عنوان باگ گزارش
می‌شود.

و **اسکن بدافزار**: PRD بند ۱۳.۲ می‌گوید «نبود آن مانع Go-live است». هنوز وجود ندارد.
جزئیات در `PERMISSION_MAPPING_DECISION_FA.md`.
