# چک‌لیست اتصال ماژول مالی به داشبورد بامبو

تاریخ: ۱۷ شهریور ۱۴۰۵ — 2026-09-08

هر چیزی که باید از تیم سایت اصلی گرفته شود تا این ماژول داخل `dash.bambo.one` بالا بیاید و
درست کار کند. هر مورد می‌گوید چیست، چرا لازم است، اگر نباشد چه می‌شود، و چطور می‌شود فهمید
تمام شده.

**روش گردآوری:** اسناد و کد شاخهٔ `origin/master` مخزن FinanceBambo، به‌همراه بررسی زندهٔ
`dash.bambo.one` در همین تاریخ — هدرهای HTTP همهٔ مسیرها، متن کامل `/sw.js`، و ۲۲ فایل CSS
عمومی میزبان. صفحهٔ داشبورد پشت ورود است و بررسی نشد؛ آنچه به Session نیاز داشت به‌عنوان
پرسش ثبت شده، نه ادعا.

# اولویت حیاتی — بدون این‌ها ماژول بالا نمی‌آید

هر یک از این پنج مورد که نباشد، یا صفحه خطای راه‌اندازی می‌دهد، یا هیچ درخواستی به سرور
جواب نمی‌گیرد.

## ۱. تابع هویت و سه Adapter امنیتی

**از:** تیم Host / Core · **مالک سمت ما:** بک‌اند

**چیست.** ماژول مالی احراز هویت *نمی‌کند* و نباید بکند. فقط یک تابع از میزبان می‌خواهد که
Session خودش را بخواند و سه مقدار برگرداند: `user_id`، `organization_id`، `project_id`.
بقیهٔ زنجیره — عضویت سازمان، عضویت پروژه، نقش، مجوزها — را ماژول خودش از جدول‌های هسته
می‌خواند.

```python
application.state.auth_context_provider = CoreAuthContextAssembler(core_conn, identity)
application.state.scope_authorizer      = CoreScopeAuthorizer(core_conn)
application.state.permission_authorizer = CoreRbacPermissionAuthorizer(core_conn)
```

**چرا.** قرارداد رسمی بامبو (Integration Kit، بند Auth) مکانیزم Session را عمداً از ماژول
بیرون گذاشته. ما نمی‌دانیم کوکی است یا توکن، و نباید حدس بزنیم. یک احراز هویت ساختگی که
۲۰۰ بدهد، از یک احراز هویت واقعی قابل تشخیص نیست — تا روزی که کسی امتحانش کند.

**اگر نباشد.** هیچ‌کدام از ۵۷ مسیر API جواب نمی‌دهد. صفحه بالا می‌آید ولی همه‌جا خطا می‌گیرد.

**تأیید.** `python -m unittest tests.test_host_identity_contract -v` — ۲۰ تست، بدون نیاز به
دیتابیس. به‌علاوه: کاربر خارج از سازمان ۴۰۳، خارج از پروژه ۴۰۳، سلب فردی بر اعطای نقش
غالب، و `org_chief` بدون ترجمه از `user_roles → roles.code`.

**مدرک.** `backend/docs/HANDOFF_HOST_AUTH_FA.md` · `HOST_AUTH_ACCEPTANCE_TEST_FA.md` ·
`coreint/security.py:250`

## ۲. سیم‌کشی ۱۱ سرویس دامنه و اتصال دیتابیس

**از:** تیم Host · **مالک سمت ما:** بک‌اند

**چیست.** ماژول مالی یک *کتابخانه* است، نه یک سرویس. هیچ متغیر محیطی نمی‌خواند و خودش بالا
نمی‌آید. میزبان باید ۱۴ کلید روی `application.state` بگذارد: سه Adapter امنیتی (مورد ۱) و
یازده سرویس دامنه، هرکدام با Repository روی یک اتصال psycopg.

**چرا.** این تصمیم معماری است که ماژول را از پیکربندی و Secret میزبان جدا نگه می‌دارد. اگر
ماژول خودش DSN می‌خواند، رمز دیتابیس وارد این مخزن می‌شد.

**اگر نباشد.** مسیرهای وابسته به هر کلید غایب شکست می‌خورند — و این عمدی است.

**نکته.** نقش دیتابیسِ *اجرا* نباید حق `CREATE` داشته باشد؛ Migration با نقش Owner انجام
می‌شود (مورد ۳). یک پرسش باز: جدول‌های مالی در همان دیتابیس هسته‌اند یا دیتابیس جدا؟
`coreint` جدول‌های هسته را می‌خواند (`organization_memberships`، `project_memberships`،
`projects`، `user_roles`، `roles`، `role_permissions`، `permissions`،
`user_permission_overrides`) — پس یا یک اتصال، یا دو اتصال لازم است.

**مدرک.** `backend/docs/CORE_HOST_WIRING_FA.md` (چک‌لیست انتهای سند) ·
`backend/INTEGRATION_GUIDE_FA.md`

## ۳. اجرای Migration تا نسخهٔ 0013

**از:** تیم Core / DB · **مالک سمت ما:** بک‌اند

**چیست.** Alembic تنها مرجع Schema است. راه‌اندازی برنامه هیچ‌وقت Migration اجرا نمی‌کند؛
باید صریحاً و با نقش Owner زده شود:

```bash
export FINANCE_MIGRATION_DSN="<owner-dsn>"
alembic upgrade head
alembic current        # باید 0013 باشد
```

**چرا.** اجرای یک پروسه، رضایت به تغییر Schema نیست. Migration بخشی از *انتشار* است نه
*اجرا*، و تنها متغیر محیطی Production همین یکی است.

**اگر نباشد.** برنامه با `SchemaNotMigrated` متوقف می‌شود و می‌گوید چه دستوری را باید زد.

> **هشدار — اسناد ما با هم نمی‌خوانند.** `DEPLOYMENT_RUNBOOK_FA.md` و `FINANCE_HANDOFF.md`
> می‌گویند Head برابر `0006` است، ولی روی هر دو شاخهٔ `master` و `backend-finance` سیزده
> فایل Migration هست و Head واقعی `0013_finance_mpp_source_identity` است. همان Runbook
> می‌گوید شاخهٔ معتبر `backend-finance` است، در حالی که این شاخه ۱۲ کامیت از `master` عقب
> است. پیش از تحویل باید همکار بک‌اند اعلام کند کدام شاخه و کدام کامیت نامزد انتشار است و
> Runbook را اصلاح کند.

**تأیید.** Backup گرفته و یک‌بار روی دیتابیس یک‌بارمصرف بازیابی شده · `alembic current` =
0013 · تریگرهای تغییرناپذیری موجود · جدول عمومی `alembic_version` ساخته نشده.

**مدرک.** `DEPLOYMENT_RUNBOOK_FA.md` · `PRODUCTION_MIGRATION_RUNBOOK_FA.md` ·
`PRODUCTION_ENVIRONMENT_FA.md`

## ۴. صفحهٔ میزبان: Context، دو عنصر mount، لینک‌های سایدبار

**از:** تیم Host frontend · **مالک سمت ما:** فرانت

**چیست.** صفحه‌ای که ماژول را نشان می‌دهد باید *پیش از* اجرای `src/app/bootstrap.js` این‌ها
را داشته باشد:

- `window.__BAMBO_FINANCE_CONTEXT__` با `userId`، `organizationId`، `projectId`،
  `projectName`، `permissionCodes`، `locale`، `timezone`. مقدار `permissionCodes` باید
  همان کدهایی باشد که سرور روی آن‌ها تصمیم می‌گیرد، چون رابط از روی همین‌ها تصمیم می‌گیرد
  چه چیزی را بکشد.
- عنصر `<main id="finance-module-root">` که ماژول داخلش رندر می‌شود.
- عنصر `<div id="finance-live-region" role="status" aria-live="polite">` برای اعلام تغییر
  صفحه به صفحه‌خوان.
- `body` بدون `data-finance-runtime="standalone"` — این نشانگر فقط برای پیش‌نمایش توسعه است
  و دادهٔ Mock را فعال می‌کند.
- دو لینک در سایدبار: `#/finance` (امور مالی) و `#/finance-report` (گزارش مالی). Router
  ماژول از `hash` استفاده می‌کند.
- هنگام تعویض پروژه در هدر بامبو، Context کامل پروژهٔ جدید با این رویداد اعلام شود:
  `window.dispatchEvent(new CustomEvent("bambo:project-context-changed", { detail: { context } }))`

**چرا.** ماژول انتخاب‌گر پروژه و ورود ندارد و نباید داشته باشد؛ همه‌اش از میزبان می‌آید.
حالت پیش‌فرض `host` است و Context نامعتبر هیچ‌وقت به داده نمایشی برنمی‌گردد.

**اگر نباشد.** بدون Context: پیام «اطلاعات پروژه از سایت اصلی دریافت نشده است». بدون
`#finance-live-region`: اولین رندر TypeError می‌دهد که در `try` بیرونی گرفته می‌شود و
**کل ماژول به‌جای صفحه، کارت «راه‌اندازی ماژول انجام نشد» را نشان می‌دهد** — یعنی نبودِ یک
عنصر دسترس‌پذیری، کل ماژول را از کار می‌اندازد. این سخت‌گیری بی‌جای ماست و پیش از تحویل
نرمش می‌کنیم (مورد ۱۶).

**پرسش.** آیا صفحهٔ داشبورد جایی از `location.hash` برای کار خودش استفاده می‌کند؟ اگر بله،
با Router ماژول تداخل دارد. صفحه‌های داشبورد HTML ایستا هستند (`/dashboard.html`) پس
احتمالاً نه، ولی باید تأیید شود.

**مدرک.** `frontend/docs/HOST_PROJECT_CONTEXT_FA.md` · `HOST_RUNTIME_STARTUP_FA.md` ·
`src/app/bootstrap.js:41-42` · `src/core/config/routes.js`

## ۵. سرو فایل‌های ماژول و پروکسی API روی همان Origin

**از:** تیم Host infra (nginx) · **مالک سمت ما:** هر دو

**چیست.**

- همهٔ درخواست‌های API به `/api/projects/{projectId}/finance/…` می‌روند و باید به اپ
  FastAPI مالی برسند.
- فایل‌های ماژول (`frontend/src/**` و `frontend/public/assets/**`) باید با *همان چیدمان
  نسبی* سرو شوند؛ مثلاً `fonts.css` فونت را از `../../../public/assets/fonts/` می‌خواند.
  هیچ مسیر مطلقی در ماژول نیست، پس زیر هر پیشوندی قابل نصب است.
- `client_max_body_size` دست‌کم **۲۵ مگابایت** — سقف آپلود صوت در ماژول ۲۵ MiB و تصویر
  ۱۰ MiB است.

**چرا.** کلاینت ماژول خودش درخواست Cross-origin را رد می‌کند (`api-client.js:4-10`)، و CORS
ندارد و لازم هم ندارد. یعنی API و فایل‌ها *باید* از یک Origin سرو شوند؛ زیردامنهٔ جدا کار
نمی‌کند.

**اگر نباشد.** API روی دامنهٔ دیگر: خطای `CROSS_ORIGIN_BLOCKED` در همهٔ صفحه‌ها. سقف آپلود
کمتر: nginx با ۴۱۳ و یک صفحهٔ HTML جواب می‌دهد، که ماژول آن را به پیام عمومی تبدیل می‌کند
ولی کاربر نمی‌فهمد چرا.

**مدرک.** `src/adapters/api/api-utils.js:3` · `services/attachments.py:17-18` ·
`PRODUCTION_ENVIRONMENT_FA.md`

# اولویت مهم — بالا می‌آید، ولی بخش‌هایی کار نمی‌کند یا اشتباه کار می‌کند

## ۶. مجوز `finance_report.issue` در کاتالوگ هسته

**از:** تیم Core

**چیست.** هسته چهار مجوز مالی دارد: `finance.view`، `finance.edit`، `finance_report.view`،
`finance_report.export`. پنجمی را ندارد و همان مهم‌ترین است. یک ردیف در `permissions` لازم
است، بعد انتساب به نقش‌ها:

```
module_key='finance_report'  action_key='issue'  code='finance_report.issue'
label='صدور گزارش رسمی مالی'  group_name='مالی'
```

**چرا نگاشت نکردیم.** صدور گزارش تنها عملیاتی است که ورودی‌ها را برای همیشه منجمد می‌کند.
نگاشتش به `export` یعنی هرکه CSV می‌گیرد سند رسمی صادر کند؛ نگاشت به `edit` یعنی هرکه یک
ردیف برآورد را عوض می‌کند عدد نهایی را رسمی اعلام کند. هر دو دسترسی را بی‌صدا گشاد می‌کنند.

**اگر نباشد.** `POST /report-snapshots` برای همه، همیشه ۴۰۳ می‌دهد و دکمهٔ «ثبت گزارش
دوره‌ای» نمایش داده نمی‌شود. رفتار درست و بسته است، ولی گزارش رسمی صادر نمی‌شود.

**تصمیم‌های باز.** کدام نقش‌ها بگیرند (`org_chief` منطقی‌ترین است)؛ و مجوزهای پیشنهادی
جزئی (`finance.create_invoice`، `finance.override_progress`، …) که تا تصویب، همه روی
`finance.edit` می‌نشینند.

**مدرک.** `CORE_PERMISSION_REQUIREMENTS_FA.md` · `PERMISSION_MATRIX_FA.md`

## ۷. خوراک پیشرفت با «مقدار اجراشده»، و پاسخ به فیلد کد فعالیت

**از:** تیم Progress و تیم Planning

**چیست.** هسته می‌گوید یک Task ۳۰٪ انجام شده؛ نمی‌گوید آن ۳۰٪ چند کیلوگرم میلگرد است.
ماژول برای تبدیل پیشرفت به پول دقیقاً دومی را می‌خواهد. Port از قبل تعریف شده:
`ProgressSnapshotProvider` با `get_snapshot` و `current_snapshot`. هر ردیف تخصیص باید
`activityCode`، `resourceCode`، `unit` و `actualQuantity` داشته باشد. و **`null` با `0`
فرق دارد**: اگر مقداری ندارید `null` بفرستید، نه صفر.

پرسش برای Planning: کدام فیلد MSP کد فعالیت معتبر است؟ پیش‌فرض ما
`text1 → outline_number → wbs` یک حدس مستند است. یک جواب، یک خط پیکربندی، بدون تغییر API.

**اگر نباشد.** ماژول کار می‌کند ولی هر خط گزارش `unavailable` با هشدار `PROGRESS_MISSING`
می‌شود — وضعیتی صادقانه، نه خرابی. اگر Provider متد `current_snapshot` را نداشته باشد، روی
دیتابیس تازه هیچ مرجع Snapshotی ساخته نمی‌شود و گزارش زنده ۴۰۴ می‌دهد.

**دو قاعدهٔ گران.** با همان شناسه‌ای جواب بدهید که با آن پرسیده شده (bigint هسته، نه UUID
مالی). در نبود Snapshot، `None` برگردانید نه Header خالی.

**مدرک.** `HANDOFF_PROGRESS_PROVIDER_FA.md` · `DATA_OWNERSHIP_FA.md` ·
`adapters/ports.py:23-45`

## ۸. سیاست Service Worker میزبان برای فایل‌های ماژول

**از:** تیم Host frontend · یافتهٔ جدید از بررسی زندهٔ دامنه

**چیست.** داشبورد یک Service Worker روی `/sw.js` دارد که هر فایل `.js/.css/.woff2/.svg`
هم‌دامنه را **اول از کش** می‌دهد و کش را با `BUILD_ID` انتشارِ میزبان خالی می‌کند. مسیر
`/api/` عمداً هرگز کش نمی‌شود — این خوب است و داده‌های مالی همیشه زنده می‌مانند.

```js
NEVER_INTERCEPT_PREFIXES = ["/api/", "/projects/", "/healthz"]
STATIC_CACHE = "bambo-cache-static-" + BUILD_ID     // cache-first: js/css/fonts
```

**چرا مهم است.** اگر نسخهٔ جدیدی از ماژول مالی مستقر شود بدون اینکه `BUILD_ID` میزبان عوض
شود، کاربرانی که قبلاً صفحه را باز کرده‌اند تا انتشار بعدیِ میزبان **JS و CSS قدیمی ماژول**
را می‌بینند، در حالی که API جدید است. ناسازگاری فرانت قدیمی با بک‌اند جدید بدترین نوع باگ
است: فقط برای بعضی کاربران، و فقط تا یک تاریخ.

**گزینه‌ها.** یکی از این سه، به انتخاب میزبان: (الف) هر استقرار ماژول مالی `BUILD_ID` را هم
بالا ببرد؛ (ب) پیشوند فایل‌های ماژول به `NEVER_INTERCEPT_PREFIXES` اضافه شود؛ (ج) فایل‌های
ماژول زیر مسیری نسخه‌دار سرو شوند (`/finance/v<n>/…`).

**تأیید.** پس از یک استقرار آزمایشی، در DevTools → Application → Cache Storage ببینید
فایل‌های ماژول از کدام کش می‌آیند و نسخه‌شان تازه است یا نه.

## ۹. سیاست CSP: زمان اجباری‌شدن، و تکلیف لینک گوگل‌شیت

**از:** تیم Host infra + تصمیم داخلی ما · یافته از بررسی زندهٔ دامنه

**چیست.** همهٔ مسیرهای `dash.bambo.one` این هدر را دارند — فعلاً در حالت **فقط گزارش**،
یعنی مرورگر تخلف را در کنسول می‌نویسد ولی جلویش را نمی‌گیرد:

```
Content-Security-Policy-Report-Only:
  default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self';
  worker-src 'self' blob:; frame-ancestors 'self'; frame-src 'self'; …
```

**وضعیت ماژول.** ماژول با **همهٔ** این سیاست سازگار است: ES Module از همان Origin، CSS و
فونت از همان Origin، API فقط `'self'`، بدون Worker، بدون CDN، و `blob:` فقط برای دانلود
CSV/XLSX که CSP آن را نمی‌بندد.

**یک استثنا:** فیلد «لینک گوگل‌شیت» در ورود قیمت‌ها و اقلام، مستقیم از مرورگر به
`docs.google.com` وصل می‌شود و `connect-src 'self'` دقیقاً همین را ممنوع می‌کند. امروز کار
می‌کند؛ روزی که `-Report-Only` از هدر برداشته شود، فقط همین فیلد از کار می‌افتد و انتخاب
فایل کنارش سالم می‌ماند. ضمناً همین کار قاعدهٔ «بدون درخواست خارجی مرورگر» در README
خودمان را هم نقض می‌کند.

**پرسش.** برنامهٔ اجباری‌کردن CSP چه زمانی است؟ و اگر قرار است ماژول داخل iframe باشد (نه
mount مستقیم)، `frame-ancestors 'self'` و `X-Frame-Options: SAMEORIGIN` فقط iframe
هم‌دامنه را مجاز می‌کنند.

**تصمیم ما.** پیش از اتصال، یا فیلد لینک گوگل‌شیت حذف/پنهان شود، یا دانلود از گوگل به یک
endpoint بک‌اند منتقل شود (مرورگر ← سرور ما ← گوگل) که هم CSP و هم قاعدهٔ README را راضی
می‌کند.

## ۱۰. Adapter ذخیرهٔ فایل تولیدی

**از:** تیم Host infra

**چیست.** فقط دو متد: `put(metadata, content) → stored_name` و
`get(organization_id, project_id, file_id) → bytes`. هر چیز دیگر — Hash، اعتبارسنجی نوع از
روی بایت‌ها، سقف حجم، حذف منطقی — کار ماژول است. تنها پیاده‌سازی موجود (`LocalFileStorage`)
در پوشهٔ توسعه است و Production عمداً به آن دسترسی ندارد؛ یک تست این را قفل کرده.

**مرز مجوز.** **هر دو کلید مستأجر باید در `get` اعمال شوند.** Storageی که فقط با `file_id`
جست‌وجو کند یک IDOR کامل است؛ «غیرقابل حدس بودن» کنترل دسترسی نیست.

**اگر نباشد.** مسیرهای فایل و استخراج کار نمی‌کنند؛ بقیهٔ ماژول سالم است.

**مدرک.** `PRODUCTION_FILE_STORAGE_FA.md` (چک‌لیست انتهای سند)

## ۱۱. Session: کوکی یا توکن، و آیا CSRF لازم است

**از:** تیم Host

**چیست.** کلاینت ماژول هر درخواست را با `credentials: "same-origin"` می‌فرستد — یعنی کوکی
هم‌دامنه را می‌برد — ولی **هیچ هدر CSRF نمی‌فرستد** و هیچ توکنی از جایی نمی‌خواند. نه در
فرانت و نه در بک‌اند مالی هیچ اثری از CSRF نیست.

**چرا مهم است.** اگر Session بامبو کوکی‌محور است و روی درخواست‌های نوشتنی (POST/PATCH) توکن
CSRF می‌خواهد، همهٔ ثبت‌ها (فاکتور، قیمت، تأیید) ۴۰۳ می‌گیرند در حالی که خواندن‌ها کار
می‌کنند — حالتی که در تست سطحی دیده نمی‌شود.

**پرسش.** Session کوکی است یا توکن؟ اگر کوکی، `SameSite` چیست و CSRF چطور اعمال می‌شود
(هدر؟ فیلد فرم؟ Double-submit؟) تا ماژول همان را بفرستد. اگر توکن، از کجا و با چه هدری.

**مدرک.** `src/core/api/api-client.js:19,32` · `PHASE5A_HOST_AUTH_BLOCKER_FA.md`

## ۱۲. قرارداد Style — تأییدشده، با یک Token کم

**از:** تیم Host frontend · تأیید زنده از `dash.bambo.one/styles/`

**یافته.** فایل‌های Token میزبان (`tokens/colors.css`، `dimensions.css`، `effects.css`)
عمومی‌اند و با ماژول مقایسه شدند: **۸۹ از ۹۰ Token ماژول با همان نام و همان مقدار روی
میزبان هست** (`--color-surface-page: #0a1120`، `--header-height: 3.5rem`، …). هر دو
`data-theme` را روی `html` می‌گذارند، هر دو فونت Vazirmatn دارند، و Reset میزبان (`button`،
`a`، `img`، `input`) با Reset ماژول یکی است — پس چیزی به داخل ماژول نشت نمی‌کند.

**سه نکته.**

- میزبان `--color-text-secondary` را ندارد و ماژول ۴۰ بار از آن استفاده می‌کند.
  `tokens.css` ماژول خودش تعریفش می‌کند؛ پس یا `index.css` ماژول کامل بارگذاری شود
  (توصیه)، یا میزبان این یک Token را اضافه کند.
- میزبان Vazirmatn را با چند فایل وزن ثابت دارد و ماژول با یک فایل Variable. هر دو با نام
  `"Vazirmatn"` ثبت می‌شوند؛ برای یک دانلود کمتر می‌توان `fonts.css` ماژول را در حالت Host
  حذف کرد. تصمیم میزبان.
- Container اسکرول میزبان (`.app-shell`) `overflow-x: hidden` دارد. ماژول در ۱۷۱ اجرای
  ممیزی از عرض ۳۶۰ به بالا سرریز افقی ندارد؛ در ۳۲۰ صفحهٔ گزارش دوره‌ای ۳۶ پیکسل سرریز
  دارد که با این تنظیم فقط بریده می‌شود، نه اینکه صفحه را خراب کند.

**مدرک.** `frontend/docs/HOST_STYLE_CONTRACT_FA.md` · `src/shared/styles/base.css`

# پرسش‌هایی که فقط تیم میزبان می‌تواند جواب بدهد

این‌ها را یک‌جا بفرستید؛ هر جواب یک تصمیم را می‌بندد.

1. Session کوکی‌محور است یا توکن‌محور؟ شناسهٔ کاربر UUID است؟ `organization_id` از Session
   می‌آید یا از مسیر درخواست؟
2. هویت چطور به FastAPI می‌رسد — Middleware، Dependency، یا `request.state`؟ در نبود
   Session معتبر چه می‌شود و با کدام کد وضعیت؟
3. آیا درخواست‌های نوشتنی CSRF می‌خواهند؟ با چه مکانیزمی؟
4. جدول‌های مالی در همان دیتابیس هسته ساخته می‌شوند یا دیتابیس جدا؟ چه کسی و کِی
   `alembic upgrade head` را می‌زند؟
5. ماژول مستقیم داخل صفحه mount می‌شود یا داخل iframe؟
6. آیا صفحهٔ داشبورد از `location.hash` برای کار خودش استفاده می‌کند؟
7. سیاست Service Worker برای فایل‌های ماژول: بالابردن `BUILD_ID` با هر استقرار مالی،
   افزودن پیشوند به فهرست استثنا، یا مسیر نسخه‌دار؟
8. CSP چه زمانی از Report-Only به اجباری تبدیل می‌شود؟
9. `client_max_body_size` روی مسیر آپلود فایل مالی چقدر است؟
10. کدام فیلد MSP کد فعالیت معتبر است؟ (پیش‌فرض ما: `text1`)
11. کدام نقش‌ها `finance_report.issue` بگیرند؟
12. آیا Gateway خطاها را در قالب دیگری می‌پیچد و `X-Request-ID` را pass می‌کند؟
