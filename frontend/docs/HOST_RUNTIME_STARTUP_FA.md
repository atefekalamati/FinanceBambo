# راه‌اندازی ماژول مالی در سایت اصلی

حالت پیش‌فرض ماژول `host` است. سایت میزبان باید Context معتبر را پیش از اجرای `src/app/bootstrap.js` در `window.__BAMBO_FINANCE_CONTEXT__` قرار دهد. نبود Context یا نامعتبر بودن آن راه‌اندازی را متوقف می‌کند و پیام خطا نشان می‌دهد؛ داده Mock نمایش داده نمی‌شود. پس از رفع مشکل Context، صفحه دوباره بارگذاری شود.

پیش‌نمایش مستقل `frontend/index.html` صریحاً `data-finance-runtime="standalone"` را روی body دارد. این نشانگر فقط برای توسعه است؛ صفحه نهایی سایت اصلی باید `data-finance-runtime="host"` داشته باشد یا این ویژگی را حذف کند. Context معتبر حتی در پیش‌نمایش مستقل، API واقعی را فعال می‌کند. Context نامعتبر هرگز مجوز بازگشت به Mock نیست. حالت ناشناخته نیز خطاست.

سایت اصلی مسئول ورود، تعیین پروژه و سازمان مالک و تأمین مجوزهای معتبر است؛ ماژول این اطلاعات را از localStorage یا نقش‌های حدس‌زده‌شده تولید نمی‌کند.

کلاینت مالی در درخواست JSON و دانلود هر دو قالب خطا را می‌پذیرد:

- مالی: `{ "error": { "code": "...", "message": "...", "request_id": "...", "details": [] } }`
- میزبان: `{ "code": "...", "messageFa": "...", "requestId": "...", "details": [] }`

پیام فارسی بر message اولویت دارد؛ قالب تو‌در‌تو، در صورت وجود، مرجع کد و پیام است. شناسه پیگیری از error، سپس بدنه اصلی و سپس هدر `X-Request-ID` خوانده می‌شود. در پاسخ خالی یا غیر JSON، کد `HTTP_<status>` و پیام عمومی استفاده می‌شود؛ متن خام HTML نمایش داده نمی‌شود. Cookie هم‌دامنه و محدودیت Same-Origin حفظ شده‌اند.

این تغییرات نصب Backend، اتصال دیتابیس یا ایمن‌سازی کامل تعویض زنده پروژه را تأیید نمی‌کنند. مدیریت درخواست‌ها و پنجره‌های پروژه قبلی، موضوع مرحله بعد است.
