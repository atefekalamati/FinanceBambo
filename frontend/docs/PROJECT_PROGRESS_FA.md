# وضعیت و برنامه پیشرفت Frontend مالی BAMBO

## بهبود خوانایی گروه‌های جدول ریز برآورد — ۱۴۰۵/۰۶/۱۸

- ردیف فعالیت پس از بازشدن، نام ستون‌های خالی خود را همان‌جا تکرار می‌کند تا کاربر برای بازیابی عنوان ستون مجبور به بازگشت عمودی به سر جدول نباشد؛ سلول‌های دارای مقدار واقعی دست‌نخورده می‌مانند.
- این رفتار به‌صورت اختیاری در جدول مشترک پیاده شد و فقط جدول «ریز برآورد پروژه» آن را فعال می‌کند، بنابراین سایر جدول‌های گروه‌بندی‌شده تغییری نمی‌کنند.
- ردیف‌های قلم زیر هر فعالیت با یک خط ظریف در لبه خواندنِ ستون ثابت مشخص شدند تا رابطه والد و زیرمجموعه در RTL و تمام اندازه‌های صفحه واضح بماند.
- تست واحد تصمیم نمایش عنوان تکرارشونده اضافه شد و بررسی نحوی فایل‌های درگیر موفق بود.

## هم‌ترازی منحنی مالی با دوره واقعی Snapshot — ۲۰۲۶-۰۹-۰۹

- Reader فایل MPP اکنون `Status Date` خود فایل را استخراج می‌کند. مسیر Core آن را به فیلد جلالی Snapshot تبدیل می‌کند و مسیر Finance-owned آن را با Migration `0014` در `finance_mpp_source_versions.reporting_date` نگه می‌دارد؛ فقط فایل‌های قدیمی فاقد این مقدار از تاریخ Import استفاده می‌کنند.
- فهرست Snapshotها نسخه جاری Finance-owned را حتی پیش از Pin شدن، بدون نوشتن در درخواست GET، نمایش می‌دهد و Feed/Overview آن نسخه با UUID پایدار خود فایل قابل خواندن است.
- درخواست `/reports/monthly` شناسه `progressSnapshotId` را می‌پذیرد و در صورت ارسال، تاریخ خود Snapshot بر تاریخ Cache‌شده فرانت اولویت دارد. پاسخ، `reportingDate` و `actualDataThroughDate` را جدا برمی‌گرداند تا تاریخ دوره با آخرین سند مالی اشتباه نشود.
- صفحه نمای کلی و گزارش‌ساز شناسه همان Snapshot انتخابی را به منحنی می‌فرستند. Mock نیز دیگر برنامه ماهانه ساختگی ترسیم نمی‌کند؛ تا وقتی Backend برنامه زمان‌بندی‌شده معتبر ندهد، خط برآورد مخفی و وضعیت آن «ناموجود» می‌ماند.
- آزمون‌های مرتبط: کل ۴۱۹ تست Frontend، ۷۰ تست Monthly/Progress، ۴۹ تست Import و ۲۴۸ تست یکپارچگی Core/Finance موفق. اعمال Migration `0014` پیش‌نیاز استقرار Backend جدید است.

## هدر مشترک صفحات داخلی — ۲۰۲۶-۰۹-۰۹

- هر ۱۳ صفحه داخلی از کامپوننت مشترک `finance-page-header.js` استفاده می‌کنند: تنها عنوان h1 و لینک بازگشت به گزارش مالی در هدر قرار دارند. توضیحات و سرعنوان تزئینی هدر حذف شده‌اند.
- کنترل‌های ثبت فاکتور، بارگذاری، چاپ و تاریخ گزارش حفظ شده‌اند و بیرون هدر قرار دارند. API، دسترسی‌ها و محاسبات مالی تغییر نکرده‌اند.
- ظاهر پایه عنوان‌ها حفظ شده؛ چیدمان دوطرفه و دکمه شفاف با حاشیه، فوکوس کیبورد و اندازه‌های واکنش‌گرا در استایل مشترک تعریف شده است. نوار عملیات در چاپ پنهان می‌شود.
- تست ساختار هدر و استفاده مشترک همه صفحات اضافه شد؛ ۴۱۹ تست Node موفق. بررسی Chrome در ۷۶ حالت مسیر/عرض (۳۲۰، ۴۸۰، ۷۶۸ و ۱۴۴۰ پیکسل) هیچ ایراد ساختار، هم‌ترازی یا برش متن هدر نشان نداد؛ اسکرین‌شات گرفته نشد.
- در بررسی عمومی همان اجرا، محتوای صفحه گزارش دوره‌ای در عرض ۳۲۰ پیکسل ۳۶ پیکسل سرریز افقی داشت، بدون ایراد هم‌ترازی هدر یا خطای Runtime. این مورد خارج از تغییر هدر است و برای بررسی بعدی ثبت شد.

## گسترش انتخاب‌گر گزارش اختصاصی — ۲۰۲۶-۰۹-۰۸

- کاتالوگ به ۲۰ گزارش رسید؛ هفت گزینه جدید شامل بودجه تکمیل، هزینه هر مترمربع، اقلام بدون قیمت، اسناد فروشندگان، اسناد منتظر تأیید، برگشت/اصلاحی و مقایسه برآورد اولیه با جاری است. شش چیپ اصلی حفظ شدند و دو دسته «بودجه و تکمیل پروژه» و «پیگیری اقلام و اسناد» به انتخاب‌گر اضافه شد.
- همه گزینه‌ها از داده‌ها و مسیر دریافت فعلی گزارش‌ساز و قالب چاپ مشترک استفاده می‌کنند؛ endpoint یا رفتار بکند جدیدی تعریف نشده است. گزارش فروشنده جمع اسمی اسناد را جدا بر اساس وضعیت/منبع نشان می‌دهد، نه بدهی یا پرداخت. مقایسه برآورد، تاریخچه کامل بازنگری نیست.
- فهرست دسته‌ها و گزینه‌های هر دسته سقف ارتفاع min(24rem, 48dvh)، اسکرول داخلی و حفظ فوکوس هنگام بازگشت دارند. دکمه ساخت خارج از ناحیه اسکرول باقی می‌ماند.
- ۴۱۲ تست Node موفق؛ تست Chrome بدون اسکرین‌شات در عرض‌های ۳۲۰، ۴۲۵، ۷۶۸ و ۱۳۶۶، با افزودن ۴۰ گزینه آزمایشی، اسکرول، حفظ انتخاب و قابل‌مشاهده‌بودن دکمه ساخت را تأیید کرد. هفت گزارش جدید با داده تستی در ۸ صفحه چاپ شدند و خطای Runtime نداشتند. ایراد قبلی چاپ صفحه reports (۲ صفحه در برابر انتظار ۱) همچنان خارج از این تغییر باقی است.

## به‌روزرسانی گزارش‌ساز — ۲۰۲۶-۰۹-۰۸

- شش چیپ پیشنهادی: خلاصه وضعیت مالی، ترکیب هزینه، گزارش مالی مراحل سطح ۱، منحنی S مالی، کیفیت داده و محاسبات، فاکتورها و اسناد مالی. سایر گزینه‌های کاتالوگ حذف نشده‌اند.
- سطح ۱ از `/reports/live/by-wbs` خوانده می‌شود: برآورد اولیه/اصلاح‌شده، واقعی، باقیمانده، بودجه تکمیل، پیش‌بینی، انحراف، شمارنده‌ها، تفکیک نوع قلم و هزینه‌های فاقد تخصیص. مقادیر null و وضعیت ناقص حفظ می‌شوند؛ 404 به‌صورت عدم دسترسی به گزارش اعلام می‌شود.
- منحنی S جمع دقیق IRR در بازه موجود `/reports/monthly` است، نه ادعای جمع کل از آغاز پروژه. برنامه فقط با داده کامل رسم می‌شود؛ Backend فعلی برنامه ماهانه ندارد. داده ناقص، ماه مفقود و اصلاحات منفی تست شده‌اند.
- گزارش فاکتورها همه صفحات API را دریافت و سپس با تاریخ فاکتور فیلتر می‌کند؛ تغییر شمارنده/تکرار رکورد/فهرست ناقص به خطای قابل تلاش مجدد منجر می‌شود. مجموع اسمی اسناد به‌عنوان هزینه واقعی معرفی نمی‌شود. فایل تصویری پیوست‌ها در این گزارش تعبیه نمی‌شود؛ شناسنامه اسناد، منبع و ارتباط سند اصلی نمایش داده می‌شوند.
- قالب A4 با سربرگ مشترک بامبو، عنوان شماره‌دار، جدول‌های فشرده، سرستون تکرارشونده و شماره صفحه، بر اساس PDFهای نمونه تنظیم شد. هر گزارش فصل مستقل دارد؛ جدول بلند بدون حذف ردیف ادامه پیدا می‌کند. این خروجی زنده است و جایگزین Snapshot مالی قفل‌شده نیست.
- آزمون‌ها: ۴۰۱ تست Node موفق. تست Chrome بدون اسکرین‌شات، خروجی شش پیشنهاد در داده تستی ۱۱ صفحه، منحنی S یک صفحه؛ کنترل عرض‌های ۳۲۰/۴۲۵/۷۶۸/۱۳۶۶ بدون خروج افقی صفحه و بدون خطای Runtime. این نتایج تأیید اتصال زنده به دیتابیس میزبان نیست.
- مشکل باز خارج از گزارش‌ساز: تست عمومی چاپ صفحه `reports` هنوز ۲ صفحه در برابر انتظار ۱ صفحه دارد؛ قالب آن صفحه در این تغییر بازنویسی نشده است. این Gate عمومی همچنان باز است.

## به‌روزرسانی اتصال میزبان — ۲۰۲۶-۰۹-۰۸

- حالت پیش‌فرض Host؛ نبود Context دیگر Mock را فعال نمی‌کند. پیش‌نمایش صریح standalone حفظ شده است.
- درخواست‌ها و دانلودهای API قالب خطای مالی و قالب `{code, messageFa}` میزبان را با حفظ جزئیات و شناسه پیگیری پشتیبانی می‌کنند.
- تست رگرسیون برای حالت اجرا و هر دو قالب خطا اضافه شده است؛ راهنمای اتصال: `HOST_RUNTIME_STARTUP_FA.md`.
- اتصال زنده به API سایت اصلی و مدیریت کامل تعویض پروژه همچنان نیازمند مرحله بعد هستند.

آخرین به‌روزرسانی: ۱۴۰۵/۰۵/۲۹ — 2026-08-20

این سند مرجع زنده وضعیت توسعه Frontend است و بعد از هر Feature یا تغییر Scope به‌روزرسانی می‌شود. درصدها براساس وزن قابلیت‌های محصول و Gateهای پذیرش هستند، نه تعداد فایل‌ها.

منابع فعال از این تاریخ PRD و Integration Kit نسخه ۱.۱ هستند؛ ترتیب دقیق و اصلاحات در `docs/SOURCE_OF_TRUTH_FA.md` ثبت شده است.

## Definition of Done هر Feature

هر Feature فقط در صورت تحقق همه موارد زیر `کامل` است:
