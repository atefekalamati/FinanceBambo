## اصلاحات مؤثر نسخه ۱.۱

- تمام پول و قیمت واحد در API رشته عدد صحیح ریال است؛ مقدار دارای ممیز، حتی با بخش اعشاری صفر، رد می‌شود.
- نسخه قیمت Strict Append-only است. ثبت اصلاح با تاریخ اثر یکسان مجاز است و جدیدترین نسخه با ترتیب قطعی انتخاب می‌شود؛ رکورد قبلی و `effectiveTo` هرگز Update نمی‌شوند.
- قرارداد عمومی JSON از `camelCase` استفاده می‌کند؛ Enum قراردادی می‌تواند طبق Vocabulary منبع `snake_case` بماند.
- چرخه پردازش فایل، بازبینی استخراج و وضعیت فاکتور سه State Machine مستقل هستند.
- تصویر فقط JPEG/PNG/WebP تا ۱۰ MiB و صوت فقط MP3/M4A/WAV/OGG تا ۲۵ MiB است؛ GIF، SVG و WebM خارج از Allowlist هستند.
- مجوزهای موجود فقط `finance.view`، `finance.edit`، `finance_report.view` و `finance_report.export` هستند. مجوزهای پیشنهادی تا تأیید و Seed تیم اصلی واقعیت Production نیستند.
- PostgreSQL 16 مبنای Production است و Migration نهایی باید هم‌زمان روی PostgreSQL 18 نیز Pass شود.
- Draft ردشده یا رهاشده پس از ۹۰ روز فقط با پاک‌سازی کنترل‌شده قابل حذف است؛ Snapshot صادرشده بدون سیاست مصوب حذف زمان‌دار ندارد.

## اثر روی Frontend فعلی

- قرارداد قیمت و مبلغ ریالی با قواعد نسخه ۱.۱ تطبیق داده شده است.
- انتخاب قیمت جاری برای تاریخ اثر یکسان براساس جدیدترین Sequence قطعی انجام می‌شود.
- Context اصلی camelCase است؛ پشتیبانی ورودی قدیمی فقط برای سازگاری نسخه‌های قبلی باقی می‌ماند.
- Featureهای فایل، AI و فاکتور هنگام رسیدن به فاز مربوط باید سه چرخه وضعیت مستقل را رعایت کنند.
